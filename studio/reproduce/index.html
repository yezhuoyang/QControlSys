QuantumOS · Reproduce

Published experiments, compiled with system calls onto digital twins

Each experiment here is written as a logical program, compiled by the fault-tolerant compiler into timed system calls, and run on a digital twin of the machine the paper used. The twin executes every operation at its listed time in the Lean model of the control system, and the trace decides whether the machine kept the schedule.

How to read a page. The paper's numbers are quoted with their source. Every number the twin uses names where it comes from: the paper, a cited paper when this one gives none, or a measurement in the twin's own trace. What is measured is a property of the model, not of the laboratory hardware. Each page ends with the command that regenerates it.

The workflow

  1. Program. The experiment as a logical program, using the compiler's code declarations.
  2. Twin. The paper's device as a fixed machine: its qubits, couplers or zones, and its published durations.
  3. Compile. The compiler lowers the program against a system specification of the twin; its resource VM must admit the listing. Every placed qubit must be a qubit of the device.
  4. Run and derive. The twin runs the listing time-triggered. Durations the hardware needed enter the next specification, until every operation fits its window.

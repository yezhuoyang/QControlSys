QuantumOS · Reproduce

Reproduce published experiments with our OS design

QuantumOS is an operating system for fault-tolerant quantum computers. Programs reach the machine only through its execution interface: system calls such as request_ancilla, route, decode_syndrome and pauli_frame_update, each with a time window, which the OS executes on its control system. Here, experiments from the literature are written as logical programs and run through that interface, to see whether the OS can carry what the papers did.

How we evaluate the OS. Each experiment runs on a digital twin of the machine its paper used: the paper's device and durations, under a cycle-exact model of the RISC-Q control system. The twin is the measuring instrument, not the subject. The question is whether every system call the OS issued ran inside its window. The paper's numbers are quoted with their source, and every number the twin uses names where it comes from: the paper, a cited paper when this one gives none, or a measurement in the twin's own trace. What is measured is a property of the model, not of the laboratory hardware. Each page ends with the command that regenerates it.

From experiment to the OS

  1. Program. The experiment as a logical program.
  2. Compile to the OS interface. The fault-tolerant compiler lowers the program to a QSysASM listing of system calls, against the OS's system specification of the machine. Its resource VM must admit the listing.
  3. Execute. The OS runs each system call at its listed time on its control system: firmware on the RISC-Q cores, pulses, readouts, decodes and the Pauli frame.
  4. Evaluate on a twin. The paper's machine as a digital twin checks every call against its window. Durations the hardware needed enter the next specification, until every call fits.

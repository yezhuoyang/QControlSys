Step inside a Helios decoder link

Open a circuit taken directly from the Helios hardware design. Watch two neighbouring workers grow a shared edge, then find the clock cycle when its status becomes visible.

Read the interface first

A worker in Helios tracks a group of connected detection events. Its root is an identifier for that group. The link between two workers stores each side’s previous root, accepts a one-bit request to grow from either end, and reports when the link has reached its configured length. In the authors’ default module the length is two and each root address is 15 bits. Reset and initialization clear the stored values on a rising clock edge. Helios neighbour-link source.

Predict two consecutive rising edges

First A requests growth, then B requests growth. At the second request the counter reaches two and the full signal goes high. The registered odd-cluster signal uses the counter value from before the edge. Advance one more cycle with the odd input held high and see when the output changes. Read the same hardware two ways


The replay evaluates the gate network produced by synthesizing the authors’ SystemVerilog with Yosys 0.9. It contains 33 flip-flops and 83 combinational gates. The scene groups pins, logic gates and storage bits in schematic positions. Clock phases express evaluation order. Timing in a placed FPGA requires routing and device delays. You can inspect or edit the input rows. Omitted input fields are zero, and the first row asserts reset. Original hardware module · Synthesized gate network · Source license.

When the count changes from one to two on a rising edge, why can full change before odd?

  
  1. Full compares the current count. Odd is a register updated using the old count.
  2. The simulator assumes a slower clock for odd.

  
Both use the same clock. The source places the odd assignment inside the clocked block and the full comparison outside it.
